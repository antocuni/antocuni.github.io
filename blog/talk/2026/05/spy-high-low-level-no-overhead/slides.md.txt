# SPy: high-level Python, low-level performance, no overhead

<!-- antocuni-qr: https://antocuni.eu/talk/2026/05/spy-high-low-level-no-overhead -->

## Recap: What is SPy?

- "Variant" of Python

- 100% compat is explicitly not a goal

- Designed for safety and performance: compete with C, Rust, Go.

- Statically typed

- Interpreted **and** compiled

---

## Recap: Why?

- TL;DR: you cannot be fast without breaking _some_ backward compatibility

- Source: I have tried for 20 years (and I'm not the only one)

- **Talk**: Myths and fairy tales around Python performance

## Recap: How?

- Multiple stages of execution: `{import, compile, run} time`

- Partial evaluation

  - Don't do later what you can do now

  - Red, blue and redshifting

- Language rules *designed* to make it possible:

  - Globals and types are frozen after init

  - Static types are enforced

- **Two levels**

  - Low level fast core

  - High level "Pythonic" APIs

  - **Zero cost abstractions** <-- today's topic

## The two levels

- CPython:

  - Low-level C: ugly, hard, fast, `gdb`, `Segmentation fault`.

  - High-level Python: high-level, nice, easy, slow.


- SPy:

  - Low-level SPy: (almost) nice, (almost) easy, fast.

  - High-level SPy: nice, easy, **fast**.

## Low-level SPy

```python
# stdlib/_list.spy (simplified)
from unsafe import gc_alloc, gc_ptr

@blue.generic
def list(T):

    @struct
    class ListData:
        length: i32
        capacity: i32
        items: gc_ptr[T]

    @struct
    class _ListImpl:
        __ll__: gc_ptr[ListData]

        def __new__() -> _ListImpl:
            data = gc_alloc[ListData](1)
            data.length = 0
            data.capacity = 4
            data.items = gc_alloc[T](4)
            return _ListImpl.__make__(data)

        def append(self, item: T) -> None:
            ll = self.__ll__
            if ll.length >= ll.capacity:
                old_capacity = ll.capacity
                new_capacity = old_capacity * 2
                new_items = gc_alloc[T](new_capacity)

                i = 0
                while i < ll.length:
                    new_items[i] = ll.items[i]
                    i = i + 1

                ll.items = new_items
                ll.capacity = new_capacity

            ll.items[ll.length] = item
            ll.length = ll.length + 1

        def __len__(self) -> i32:
            return self.__ll__.length

        def __getitem__(self, i: int) -> T:
            ll = self.__ll__
            if i < 0:
                i = i + ll.length
            if i < 0:
                raise IndexError
            if i >= ll.length:
                raise IndexError
            return ll.items[i]

    return _ListImpl
```

## Climbing the abstraction ladder

- Low-level fast core + zero cost abstractions

- --> High-level fast APIs

- Advanced users

  - use SPy to write powerful and fast libraries

  - Enjoy a nicer language

- End users

  - mostly "the same python as ever"

  - no need to know about the advanced topics

  - you don't need to know C to use `numpy`

---

## Climbing the abstraction ladder

- Some examples:

  - static dispatch of operations

  - don't allocate small structs

  - metaprogramming

  - blue values to "specialize" when possible

## Small structs (1)

```python
def main() -> None:
    for i in range(10):
        print(i)
```

- Python:

  - allocate `range` object

  - call `__iter__`, call `__next__`, ... (dynamic dispatch!)

  - catch `StopIteration`

- Most Python compiler special case this particular form to make it fast

- SPy: no need for special cases

---

@struct
class range:

    stop: int
    step: int

## Small structs (3)

```python
# stdlib/_slice.spy

@struct
class Slice:
    start: i32
    start_is_none: i32  # bool
    stop: i32
    stop_is_none: i32  # bool
    step: i32
    step_is_none: i32  # bool

    @blue.metafunc
    def __new__(m_cls, m_start, m_stop, m_step) -> OpSpec:
        # For each of the 8 possible combinations of three variables which
        # can be either None and i32, create an mplementation with the
        # correct parameter types. Each implementation calls Slice.__make__
        # with the appropriate "flags" for None-ness set

        TYPES = interp_tuple(
            m_start.static_type, m_stop.static_type, m_step.static_type
        )

        if TYPES == interp_tuple(i32, i32, i32):

            def impl1(_start: i32, _stop: i32, _step: i32) -> Slice:
                return Slice.__make__(_start, 0, _stop, 0, _step, 0)

            return OpSpec(impl1, interp_list[MetaArg](m_start, m_stop, m_step))

        elif TYPES == interp_tuple(NoneType, i32, i32):
            ...
```

## Metaprogramming (2)

```python
# stdlib/_tuple.spy

@blue.generic
def tuple(*items_T):

    @blue
    def get_fields():
        """
        Return a dict like {
            "_item0": int,
            "_item1": int,
        }
        """
        fields: dict[str, type] = {}
        for i in range(len(items_T)):
            fname = "_item" + str(i)
            T = items_T[i]
            fields[fname] = T
        return fields

    N = len(items_T)

    @struct
    class _tup:
        __extra_fields__ = get_fields()

        def __len__(self) -> i32:
            return N
```
